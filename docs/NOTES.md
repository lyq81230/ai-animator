# 技术笔记与实现细节

> 本文是开发过程中积累的完整说明：每条规则背后踩过的坑、参数含义、排查方法都在这里。
> 想快速上手请看根目录的 [README](../README.md)；想改代码或理解某个行为为什么这么定，再回来看这份。

把一套**分层的角色素材**丢进来，自动生成骨骼 + 蒙皮 + 动作动画，输出 Spine 3.8 的 `result.json`。
不需要视频、不需要显卡、不需要联网。

流程是**先拆图、再做动作**：拆图（切部件 + 定坐标）独立成一步，拆对了、
确认过「拆图体检单」之后，再用同一份部件反复生成待机 / 行走 / 受击 / 死亡，
**不用每次重新拆图**。平面图的 AI 拆图一张要 2~4 分钟，这样只需要付一次。

## 一、安装

**不用装任何东西**，包里已经自带了便携版 Python 和全部依赖。

解压到任意目录（路径别带太深），双击 **`run.bat`** 即可。

> 目录里的 `python\` 就是自带的解释器，别删。
> 如果你想改用自己电脑上的 Python，把 `python\` 文件夹删掉，`run.bat` 会自动改用系统 Python，
> 并在首次运行时 `pip install -r requirements.txt`（PySide6 / numpy / Pillow / opencv-python / psd-tools）。

## 二、用法

双击 `run.bat` → 把素材拖进左上角虚线框 → **① 拆图** → 看「拆图体检单」确认拆对 →
**② 选动作** → 调幅度/速度 → 点「生成 行走」。

### 窗口尺寸

窗口不再写死 `1180×800`（在 1080p 笔记本上，算上任务栏和 125% 缩放，可用高度常常只有
700 出头，底部那排按钮会被顶到屏幕外）。现在启动时按**可用桌面**自适应：

```python
_w = min(1260, max(900, avail.width() - 80))
_h = min(900,  max(640, avail.height() - 80))
window.setMinimumSize(880, 620)
```

左栏本来就在 `QScrollArea` 里（窗口再矮也能滚到底），所以只要把内容压到 ~690px 就
不用滚：七个滑块从"一列七行"改成**两列四行**的网格，标题里带数值（`动作幅度 100%`）
省掉单独一行，组间距压到 6px。实测左栏内容 816 → **694px**，720 高的窗口正好放得下。

### 界面和命令行是同一套代码（会一起生效）

GUI 不自己算东西，它只是把参数拼成命令行去调 `build_from_seethrough.py` 和
`gen_idle_bones.py`。所以命令行里修的东西（手臂去身体、头饰清理、头盔层级、
slot 归属骨、闭眼补丁……）界面里**自动就有**，不用两边各改一遍。

界面特有的两处已经对齐：

| 项 | 说明 |
|---|---|
| 拆图命令 | 固定带 `--leg-halves --head-wear <下拉选择>`；`build` 结束时自动跑 `fix_headwear` |
| 沿用旧拆图 | 会用新规则重抠一次头饰（`_post_adopt_fix`），并提示"手臂若还带躯干请重拆" |
| 默认时长 | 与 `gen_idle_bones._ACTION_DUR` 一致（walk 2.0s），再除以 0.75 → 实际 2.67s（行走还有 `WALK_SLOW`，最终 3.54s） |

界面这一轮跟着命令行一起更新过：

| 项 | 现在的行为 |
|---|---|
| 导出 | **只出 `spine/`**（png + atlas + json）；`--dragonbones` 不再传递，`dragonbones*` 三个目录不再生成（旧的已删） |
| 文案 | 动作区/复选框/日志里不再出现"龙骨"，统一写成 "Spine 骨架" |
| 拆图 | 仍带 `--leg-halves`；同侧腿碎片会先并成整条腿再按膝高重切 |
| 层级 | 拆完按 z 序重排（腿在衣摆之后），不会再让大腿盖住身体 |

> 一句话：以前用老代码拆过、看起来"没修"的角色，点一次【① 重新拆图】就会按新规则重做
> （AI 分层有缓存，通常几秒到十几秒）。只用旧结果直接生成，也能拿到新逻辑的骨骼/导出，
> 但**手臂、头饰这类像素清理必须靠重拆**。

### 头饰（头盔/头巾）的三条硬规则

`fix_headwear.py` 在拆图最后一步自动跑（scarf / helmet 模式），现在按这三条收敛：

| 规则 | 原因 |
|---|---|
| 只补**布料色 / 金属色**像素，不再按"非肤色前景"补 | 后者会把整张脸、袍子一起框进来 |
| 下巴以下只留布料色，且整块判定"是否连到布主体" | 垂布是黄的且连着顶部；袍子/肩膀碎片在下面，整块丢掉 |
| 闭合后的内部小洞补回来 | 布/盔是实心物，中间透出背景一定是漏缝 |
| **头盔 + 头巾拆成两块**（`helmet` 模式） | 盔和系在额头上的布带 = 刚性（100% 跟 `b_head`）；只有垂到头两侧之外的布才是 `headscarf`（`cls=cloth`，走飘动链） |

生成阶段有三层保险（界面切模式 / 旧结果都能兜住）：

1. **已有 `headscarf`** → 直接把 `headwear` 的 `cls` 纠正为 `headgear`（界面切模式会把所有 `head*` 统一改成 `cloth`）
2. **还是合并的一块** → 按像素重拆（用 `headwear_full.png` 底图，或现图）
3. **拆不动但以金属为主**（S 中位数 < 60）→ 强制 `headgear`：宁可垂布不飘，也不能让盔飘

拆开这件事**在生成阶段还会再做一次兜底**：界面切换「头饰模式」会把两块并回一块（只改 coords），
于是头盔又变成 `cls=cloth` 一起飘。`gen_idle_bones.load_parts` 现在会按像素再拆一遍
（判定用「整块饱和度中位数 < 60」= 以金属为主），拆完把结果写回 coords。

> 为什么不用"有没有灰色像素"判断：头巾的金黄布里也有大片高光灰点（fa 实测 3784px），
> 用中位数才分得开 —— 头盔 S≈20，纯布头巾 S≈145。

> 为什么按**位置**拆而不是按颜色：头巾带压在额头上、紧挨帽檐，布上的暗褶子又和盔色很接近。
> 纯按颜色分，要么把盔带进布（盔跟着飘），要么把布判成盔（不透明盔把布整条盖住，只剩边缘）。
> 现在只把「落在 head 水平范围之外、且在额头以下」的高饱和布像素算作垂布，其余全归刚性头饰。


### 原图带底色时（RGB 截图），部件会拖着一块背景

`fa.png` 这种没有透明通道的截图，模型分层时会把背景也算进某一层，于是拆出来的部件
在角色周围露出一块底色方块。现在三道防线：

| 位置 | 做法 |
|---|---|
| 读图层 | 每层先跟"前景 mask"求交（`strip_bg` 从四边泛洪抠背景） |
| 拆完 | `strip_part_bg()` 再删一遍：**只删和部件外轮廓连着的**底色块 |
| 头饰 | `fix_headwear` 不再按"非肤色前景"补，改成只补**布料色/金属色**；底色、皮肤、碎块都清掉 |

> 为什么"只删贴边的"：角色身上的暗部（阴影、黑描边）颜色和深蓝底色很接近，按颜色一刀切
> 会把脸啃出一条条白带。底色块一定是连着部件外边界的，阴影不是 —— 按连通域挑就分开了。

### 白底图的"白洞"（烟雾/发丝之间的那块白）

`src_img.png` 是白底截图时，模型会把"几缕烟之间那块白"还原成**不透明纯白**。它跟着图层
被切进部件里：部件图上贴着一块白方块，拼回去烟里多两个白疙瘩。`strip_part_bg` 治不了 ——
它只删贴着部件外边界的底色块，而这块白在部件中间。

现在在 `build_from_seethrough` 读到原图之后立刻按"三通道都 >226、面积 ≥300px、且块里
≥45% 是纯白(≥254)的连通块"抠掉（`white_holes()`）。`--white-min` 可调面积门槛。
董卓那张是两个 600+px 的洞，正好命中。

**只在"白底截图"上做**：原图本来就带透明通道（抠好的立绘）时，里面的纯白是画出来的
——白刀面、金属高光——一个像素都不能动。华雄的白刃大刀就是被这条误伤的（刀面被吃成
只剩描边），所以现在先判 `alpha<12 占比 >2%` 有透明通道就直接跳过这一步。

**带透明通道的图里也可能有白底残留**：抠图工具常常漏掉"被角色围住"的那块白（华雄
刀和裙摆之间就有一块三角白，100% 近白、alpha 却是 255）。这种块不在任何模型图层里，
会被**残影补偿**当成"模型漏画的部位"捡回来，变成一块白贴图跟着手飞。现在残影补偿
会跳过"近白像素 >85%"的连通块 —— 它本来就不是角色的一部分，放过即保持透明。

### 长袍角色没有腿：模型把裙子+腿甲整块算进上衣

`legwear` 层是空的、`footwear` 只有靴子，膝盖以上全在 `topwear` 里 —— 没有 `leg_L/R`
就没有髋/膝骨，行走、受击、死亡的腿动作全做不出来（表现是"部件不够，没法生成动作"）。

`split_legs_from_body()`：髋线 = 脚底往上 0.47 个身高；线以下整体算下肢，按连通域分
左右，再按膝高切上下两段；切完**从上衣层挖走并压暗**（同 `_shade_hole`），腿
`_z_arm=22` 排到衣服前面 —— 只复制不挖的话腿被上衣盖着，走起来一动不动（和肩甲
那次踩的是同一个坑）。长袍把两腿连成一片时按中线硬切，裙摆分成两半跟着腿走，中缝
本来就是褶，看不出来。`--no-leg-from-body` 关掉。

三个后续补丁（都是被真实角色逼出来的）：

**① 没有 `footwear` 也要切。** 全身甲角色（魔身）连靴子都在 `topwear` 里，`footwear`
整层是空的。原来那句 `if not feet: return` 直接让这一步失效，界面只会报"缺腿"。
现在没有脚就用整体轮廓的底边兜底。

**② 只取两只手之间。** 双手持刃的角色，刀也在 `topwear` 里，`objects` 是空的，刀从手上
斜垂到脚边 —— 一刀切下去会把**刀刃当成腿**（魔身第一版就切出两片刀）。判据：腿一定在
两只手内侧之间，取左右手内缘当水平闸门，外面的一律不算下肢。

**③ 被闸门挡在外面的就是刀 —— 拆成道具。** `_cut_blades()` 把那几坨按连通域切出来
（先膨胀 7×7 再连通，刀身和内侧描边常常是两坨），左右各挂一只，`follow_part` 指向对应
的手，走路时跟着手走。不做这步的话，手随缩短短抬高，手就在刀柄上"滑动"。

### 后发其实是翅膀：并进头饰会把整个人罩住

头巾模式会把 `back hair / front hair / headwear` 合成一整块 `headwear`，而 `Z_RANK`
里 headwear 是 95（最上层，因为头盔不该被任何东西盖住）。长翅膀的角色模型会把整对
翅膀塞进 `back hair` —— 合并后翅膀被排到最上层，胸口、手臂全被压成一团黑噪点。

判据不能只看"这块很大"（`fa` 的头巾也占 67%×93%，并且**必须**合并）。真正管用的是
**同时**满足两条：

1. 这一层面积 > 15% 画布；
2. 另有一块**独立且很小**的 `headwear` 层（真头盔）—— 面积 < 这块的 25%。

命中就把它拆成独立部件 `wings`（`cls=body`，`Z_RANK` 里 z=4，排在最后面）。
`fa`（headwear 层为空）不会被误判。

### 头发把整张脸糊住

模型偶尔会把"前发/头饰"整块涂成实心头发：**脸的位置糊一块不透明灰**（华雄实测
rgb 90,90,90 / alpha 253），而 `Z_RANK` 里前发排在脸前面（为了压刘海），于是整颗头
被盖死 —— 拼回去就是"没有脸"。

`demote_hair_over_face()`：判据是"盖住 head 过半 **且** 脸心那块的颜色比 head 离原图
差 35 以上"（只看覆盖面积会误伤真头盔）。

命中后**并进 `head`，不再单独保留一块"头发"**：整颗头（head ∪ 头发）按原图重铺像素，
头发层从部件表里删掉。为什么不能只把头发压到后面 —— 那样这块"头发"里烘着原图的脸，
而它挂的是**发丝飘动链**（`auto_hair0_0`），一走路半张脸跟着头发甩（"头部绑定有问题"）。
并进 head 后 100% 跟 `b_head` 刚性动。

配套两条：
- head 里已经有原图的眼鼻嘴，模型再给一份就是重复（华雄的 `eyewhite` 是一块深色，
  把琥珀色眼睛整个盖住）→ head bbox 内的 鼻/嘴/眉 删掉；眼白/睫毛**留着**（生成器
  要用它们的位置做闭眼补丁），z 压在 head 下面不显示
- head 的 z 给 36.2：压住眼白(34)/睫毛(36)，又让闭眼补丁(36.5)盖得住

日志打印 `头发盖脸: headwear 覆盖 head 68% -> 脸用原图补回, 并入 head(刚性跟头)`，
`脸已按原图重铺: 去掉重复的 mouth`。

### 肩甲/大臂：模型只给"肘以下"，肩甲永远钉在躯干上

重甲角色的大护肩、布袖在 see-through 里被算进 `topwear`，`handwear` 只包含小臂+手。
结果 `arm_upper` 只剩几根描边碎线，肩甲留在躯干上不动 —— 一摆臂就是"肩不动、胳膊断开"。

`split_arm_from_body()` 从上衣层把这块切出来（不需要训练，只用几何）：

```
取形 = 8 点多边形(见 _ARM_SHAPE)，坐标全部相对【肘点 + 前臂宽高】
       内上 / 外上 / 外中 / 外下 / 肘外 / 肘内 / 内下 / 内中
```

比例是怎么来的：肘永远比肩外张（所以横向全部按"内侧/外侧"写，左右镜像）；肩甲
比前臂宽约 1.3 倍、高约 1.9 倍；内沿刚好停在胸甲金扣的外侧。**不要用椭圆/胶囊**：
圆头顶多盖住中段，左肩甲的冠和右下角都会留在躯干上 —— 那就是"左肩膀没拆出来"。

- 手臂像素**必须从上衣层挖走**：只复制不挖，上衣里那张一模一样的肩甲留在原地，
  肩甲就被钉死了（两边都像没拆，左边尤其明显，因为左肩甲几乎和上衣完全重合）
- 挖出来的洞用 `_shade_hole()` **压暗当投影**（×0.55）。inpaint 会揉成灰糊；
  "边界颜色向内扩散"会把胸甲的灰顺着洞长出一只假肩甲，比洞还难看。压暗后手臂
  盖着看不见，臂骨走 1~2px 露出来是一条暗边，像投影
- 紫烟像素不从上衣层挖（烟是环境，不该跟胳膊走），但手臂图里保留（否则肩甲缺口）
- 手臂 `_z_arm=22` 压在 topwear 前面；`gen_idle_bones` 里大臂的竖向缩放只给 1%
  （原来 2.8% 会把整块肩甲从身上"抬起来"4px）
- 只在"新增面积 > 35% 才切"，正常角色（quan/suo/pi，大臂本来就独立）会被跳过；
  `--no-arm-from-body` 关掉，`--arm-from-body` 强制切

### 速度：为什么"拉长时长"不等于"变慢"

行走是**循环**，相位必须走整数个周期，否则首尾接不上。所以早期那种"只把时长从 2.0s
拉到 2.67s"的做法并不会变慢 —— 它只是让一个循环里多塞几步（2.67s 走 6 步 = 2.25 步/秒，
比设定的 2.0 还快）。

现在的做法是分开算：

```python
cad    = 2.0 * 用户倍率                     # 决定"几步"
cycles = round(dur * cad / 2)               # 整数个左右周期（两步一周期）
T      = dur / WALK_SLOW                    # 时间轴拉长 → 每步走得更久
```

- `SPEED_BASE = 0.75`：时长统一 ×1/0.75（所有动作）
- `WALK_SLOW = 0.75`：行走再单独放慢一档（步数不变、时间 ×4/3）

**当前实测**：6 步 / 3.54s = **1.69 步/秒**，是上一版（6 步 / 2.67s，2.25 步/秒）的 **75%**。
界面上「播放速度」滑块 100% 就是这一档，往左拉还会更慢（步数会按整周期减少）。

### 「保留已有动作」不再被记住

这个开关决定"文件里到底有几条动画"。以前它会被存进注册表，只要勾过一次，之后每次生成
都悄悄把上次的旧动作并回来 —— 表现就是"没勾待机却出现待机"。现在**每次启动都是不勾**，
要保留旧动作就当场勾一下，生成完关掉即可。

### 动作按钮怎么选

**启动时默认勾「行走 / 受击 / 死亡」**（待机不勾，需要时手动点），点几下就有几个，
界面不做任何"自动帮你加/减"：

| 操作 | 结果 |
|---|---|
| 启动时 | 行走 / 受击 / 死亡 已勾，待机未勾 |
| 点一个动作 | 只切换它自己的勾选 |
| 再点已勾的 | 取消这条（但至少会留一条） |
| 「全选动作」 | 4 条一起勾 |
| 一条都没勾 | 生成按钮变灰，提示「先勾一个动作」 |

勾了什么，底部实时写 `本次只生成: 待机、行走（2 条）`，生成按钮上也列出来。

> 折腾过两轮才定成现在这样：
> - 一开始**默认勾着待机**，用户点行走时待机没被取消 → 抱怨"没选待机却冒出待机"；
> - 于是加了条"第一次点击先取消默认勾的待机"→ 用户依次点 行走/受击/死亡，待机被
>   **悄悄踢掉**，导出来只有三条 → 抱怨"未生成需要的动作"。
>
> 两条抱怨其实是同一件事：**界面高亮的 ≠ 实际会被生成的**。现在不预勾任何东西，
> 高亮什么就生成什么，两边不会再错位。

### 摆臂怎么"看出来"是前后

正面角色没有真实的 z 位移，前后摆只能靠三样东西。**顺序很重要**：从前到后依次是
"缩短 / 抬升"占主，"左右摆"只占一点点 —— 反过来做，看着就是"手在左右甩"。

| 相位 | 大臂（肩，含护肩甲） | 小臂 |
|---|---|---|
| **前摆** | 抬 2.0px、**内收 2.6px**、`scaleY 0.945`、转 +1.4° | `scaleY 0.92`（锚点在**肘**）、肘弯 2.0° |
| **后摆** | 落 0.9px、外撇 1.3px、`scaleY 1.026`、转 −0.8° | `scaleY 1.035`、肘伸直 |

> 为什么是"缩短"主导：`scaleY` 的锚点在小臂的**肘**，一缩就是护腕+手+整个刀一起往上收，
> 接缝纹丝不动 —— 这就是观众看到的"手往前伸、看着变短"。
> 反过来用旋转表达"向前"，在 2D 里就是**左右横扫**：手部横向行程 11.8px vs 脚 23px 时，
> 用户的原话是"仅左右摆效果明显，缩短的效果不明显"，而且护肩甲会在胸口上滑来滑去。

**两段都要压扁**。只压小臂、大臂不动的话，上臂看着还是一截生硬的直线，
用户会直接指出"手的上半部分未压扁"。现在大臂 5.5%、小臂 8%，加起来肩→手缩短 **22%**。

**旋转必须压到 2° 以内**。骨骼旋转在立面图上没有"前后"，只有"左右"：转 5.8° 时，
护肩甲绕肩关节画一个 5px 的弧，看起来就是"肩甲在胸口滑动、和身体连接处动作太大"。

**"向身体中线收"要看相对量**。整个身体每步都在左右移重心（`--sway` 4px），绝对坐标会被它
盖掉：实测手在**绝对坐标**上是往外 -4px，而**相对躯干**其实是往内 +3.8px。判据一律用
"手相对躯干的横向偏移，取手最高帧 − 手最低帧"，4~8px 才算"少许内收"。现在 **+6.2px**。

**肩膀仍要有一点摆动**（±2°、2.6px），否则整条胳膊像焊在躯干上。肩角是**整个乘 `sign`** 的：

```python
sr(b, sign * (arm_swing * k * 0.06 * sin(p_arm) + (1.4 * fwd - 0.8 * bwd) * k))
```

为什么不乘会出问题：`0.16*swing*sin` 是"侧向摆"的符号约定，和"前后摆"相反。不统一符号时，
一侧相加、另一侧相消 —— 实测左肩 `-2.6°~+4.0°`、右肩 `-1.1°~0°`，一边在动一边像焊死。

两组动作**同一个带符号的信号**驱动（`sin(对侧腿相位)`），所以严格 1:1 同相，不会出现"腿一步、
手两下"（早期用 `|sin|` 表示抬臂，前摆后摆都抬，节奏就变成腿的两倍，看着对不上腿）。

实测：左手高度 vs 右腿脚高 相关 **0.9**，相位差 0 帧。

> 量法：`python measure_motion.py output/<名字>/spine/<名字>.json walk`
> 按骨骼时间线做正向运动学，打印行程和三个判据：
>
> | 指标 | 现在（华雄） | 合格区间 |
> |---|---|---|
> | 肩→手 长度缩短 | **11.7%** | 8~15%（按肩→手全长算，<6% 就只剩左右摆） |
> | 前摆时手向身体中线 | **+8.4 px** | 4~8px（负值就是往外撇） |
> | 手/脚 横向行程比 | **0.11** | 0.1~0.3（>0.45 就是"左右甩"） |
> | 手/脚 竖向行程比 | **1.63** | 1.0~1.6 |
>
> 改幅度别凭眼睛看预览 —— 缩略图里 4px 和 12px 几乎一样。

### 肩 / 肘 / 腕 的支点必须落在【接缝】上

三段手臂是**各自 100% 绑自己那根骨**的（`arm_upper → arm_L_up`、`arm_fore → arm_L_fore`、
`arm_hand → arm_L_hand`），所以支点位置只要偏一点，两截就会绕着错的点转 —— 表现就是
"手臂上下两截没绑在一起""手跟着小臂跑出去了"。

早先的算法有两处错：

| | 旧写法 | 现在 |
|---|---|---|
| 肩点 | 离 `(身体中线, 躯干中部)` 最近的顶点 —— 躯干中部在**大臂下半**，肩点落到肘上 | 部件**上沿 28%** 里最靠身体中线的那一点 |
| 肘 / 腕 | `远离肩的点 + 靠近肩的点` 取中点 —— 部件一重叠（护腕套在袖子上）就跑到大臂中间 | 两段部件顶点云的**最近点对**中点 = 真实接缝 |

实测（华雄，画布坐标）：修之前 `arm_L_up` 落在 (118, **151**) = 肘、`arm_L_fore` 落在
(120, **105**) = 肩上方（整条链是反的）；修之后是 **肩 (141, 82) / 肘 (117, 151) / 腕 (95, 220)**，
正好压在 `arm_upper`(59..154) / `arm_fore`(144..221) / `arm_hand`(218..277) 的接缝上。

> 腿也一样按接缝放（髋=腿甲顶、膝=大腿/小腿交界、踝=小腿/靴子交界），靴子 100% 绑踝骨。
> **这项只影响生成骨骼，不影响拆图**：老的结果不用重拆，重新点一次生成即可。

### 道具（刀/盾）挂独立骨，而且必须挂在【手】上

道具原来直接共用小臂那根骨，手臂靠 `scaleY` 缩短时，刀会被一起压扁（8% 缩短 = 136px 的
刀短 11px，一动一缩像橡皮）。现在 `build_skeleton` 给每个 `follow` 道具挂一根独立子骨
`prop_<名字>`，**位置放在手骨（`arm_*_hand`）处、父骨仍是小臂**，走路时把父骨链的缩放除回去：

```python
_sy = 大臂scaleY * 小臂scaleY        # 父骨链上的总缩放
ss(prop_bone, 1.0, 1.0 / _sy)       # 只补缩放, 旋转/位移照常继承
```

> **位置必须在手上，不能放肘部。** 缩放的锚点在小臂的肘，所以缩短时拳头随小臂整体上移
> 8~11px；道具骨要是放在肘部，刀就留在原地不动 —— 表现就是"武器没跟手"（踩过一次）。
> 挂到手骨处，拳头和刀以同一个点为基准上下走，握持关系始终不变。

刀跟着手走、长度不变。导出里会多一根骨（`prop_objects`），LoongBones 照常认。
`measure_motion.py` 里可以验证：`手骨-道具骨` 距离全程应恒为 0。

### 肩、肘、手必须是"一条胳膊"

骨链是 肩(`arm_*_up`) → 肘(`arm_*_fore`) → 手(`arm_*_hand`)，Spine 里子骨相对父骨，
所以**世界角 = 三段的局部角相加**。判断协调不协调，看的是世界角，不是单段数字。

两条硬规则：

**1. 肘角必须和肩角同向**（都乘 `sign`）。以前只有肩乘、肘没乘，于是左臂"肩往前摆、
肘往后折"（世界角 3.6° 被抵消成 1.1°），右臂"肩往后摆、肘又跟着折"（世界角 -6.2°）——
同一帧左右差 5° 以上，看着就是两个关节各走各的。现在肘角 `max(0, ·)` 且同号，
左臂世界角 `3.64 → 5.79 → 6.41`，右臂镜像，肘也不会反折过直线。

**2. 小臂不许写 `translate`**。肘骨就落在"袖口和大臂末端"的接缝上，给小臂加位移等于把
护腕从袖口揭下来 —— 原来是 `(2.8, 4.2)px`，走动时肘部一条 4px 的缝忽开忽合。
手的总行程改由**绕肘旋转**给（转多少度都不会脱开），前摆的"手抬起来"由
`scaleY 0.955`（锚点在肘，向上缩）补足。

待机同理，而且**三段要沿链条递减**（肩 > 肘 > 腕）：

| | 旧 | 新 |
|---|---|---|
| 局部角（肩/肘/腕） | 2.2 / 3.5 / 5.0 | 3.4 / 1.5 / 0.7 |
| 世界角（累加） | 2.2 / 5.7 / **10.7** | 3.4 / 4.9 / **5.6** |

旧值等于"肩甲几乎不动、手甩了 5 倍"，就是用户说的"肩膀与前臂的运动不匹配"。
参数在 `app.py` 的 `PARAMS` 和 `gen_idle_bones.py` 的 `--sh/el/wr-deg` 两处**都要改**
——界面的值会覆盖命令行默认值。

### 「拆图能不能用」按角色查，不按部件个数

界面和生成器原来各写了一条 `len(parts) < 20` 就判"这份拆图结果不可用"，拦在生成之前。
这条件会**误杀**：模型的 slot 每版给的东西不一样，华雄的头发+五官并进 `head`、靴子并进
`leg_low` 之后只剩 18 个部件 —— 腿×4、脚×2、大臂×2、小臂×2、手×2、躯干、头、眼睛、
睫毛、闭眼补丁、道具一件不缺，四条动作全都能出，却被门禁挡住，界面表现就是
「拆了也点不动生成」。

现在统一到 `parts_check.py`，按**功能角色**查：

| | 角色 |
|---|---|
| 必需 | 腿（`cls=leg` / `leg_*`）、大臂、小臂、躯干/衣服、头（或 `face`） |
| 可选 | 脚、手（很多模型的靴子并进腿、手并进小臂，缺了照样出动作，只是少一段独立骨） |

- `check_parts(parts)` → 缺的必需角色（空 = 可用）
- `missing_optional(parts)` → 缺的可选角色（只提示，不拦）
- `note_of(parts)` → 界面状态栏那一行，解释"18 个部件"是怎么来的：
  `已拆图 · 18 个部件（头发/五官并进 head、死亡闭眼补丁）· 可做动作`

三处共用：`app.py` 的 `_load_split()` / `_adopt_legacy_split()`、`gen_idle_bones.py` 的
生成前体检。加新角色（比如以后要拆独立的眉毛）就往 `_ROLE_RULES` 里加一行，别再数个数。

### 先拆图，再做动作（重要）

程序是**两步**的，不是一次到底：

| 步骤 | 做什么 | 产物 |
|---|---|---|
| **① 拆图** | 把素材切成一个个部件（头发/脸/眼/手臂三段…），算好每个部件的坐标 | `output\<素材名>\parts\` + `coords.json` + `_split_preview.png` |
| **② 动作** | 只读上面拆好的 parts，生成骨骼 + 蒙皮 + 动作（可一次勾多个动作） | `output\<素材名>\<动作>\result.json` + `output\<素材名>\dragonbones\`（龙骨，一个骨架多条动画） |

**拆图正确之后，四种动作可以反复生成，不用再拆一次。**
平面图的 AI 拆图一张要 2~4 分钟，所以这一步单独拎出来：
拆一次 → 出待机 → 改幅度再出 — 出行走 → 出行走 → 出受击 → 出死亡，全都复用同一份 parts。

拆完图右边会自动出**「拆图体检单」**，用来判断拆得对不对：

- 左边：所有部件按坐标合成回来的成品（棋盘格背景），每个部件带编号框；
- 右边：每个部件的缩略图 + 名字 + 程序判定它是什么（头发/大臂/小臂/手/眼…）。

检查要点：**该有的部件都在**（手、脚、前发、后发）、**手臂是否分成三段**、
**脸上五官是否各自独立**、部件边缘有没有把别的部位一起带走。
名字颜色发黄 = 名字没命中关键词，会被当普通躯干处理（见第四节）。
拆错了点 **① 重新拆图** 即可，体检单也会跟着重出。

**「头部装饰」下拉框（有头发 / 头巾 / 头盔）**

模型分不清"头发"和"头巾、头盔"，都会塞进 `前发 / 后发 / 头饰` 三个槽位。
这一项就是告诉程序它到底是什么，三种模式差别很大：

| 选项 | 处理 | 效果 |
|---|---|---|
| **有头发**（默认） | 不合并，按名字当头发 | 刘海/马尾正常吹风飘动，后发有惯性滞后 |
| **头巾（可飘）** | 合并成一整块，`cls=cloth` | 包在头上的那圈**钉死不动**，垂下来的下摆会飘 —— 布的东西（权重按"离头多远"分，根段摆幅为 0） |
| **头盔（刚性）** | 合并成一整块，`cls=headgear` | 整块 100% 跟 head，一点都不飘，也不参与脸/颈权重混合 —— 硬壳 |

**头巾和头盔都会合并成一整块** `headwear`，像素直接取自原图，所以不会出现
"前布 + 后飘带 + 补丁"三片拼回去有接缝、颜色串掉的问题。
区别只在 `cls`：`cloth` 走风链（根段摆幅 0，只有末端飘），`headgear` 完全刚性。

> 合并是**拆图时**做的，所以改完选择要重跑一次 ① 拆图（AI 分层有缓存，几秒）。
> 只改下拉不重拆，坐标里的 `cls` 会立刻生效，但碎片还是分开的（日志会提示）。

选择会记住（下次开程序还在）；已经拆好的图**改下拉会立刻重写坐标**，
不用重新拆图，体检单也会重出（标签在"头发(风吹)/头巾(下摆可飘)/头巾/头盔(随头)"之间切换）。

拆图状态会显示在「① 拆图」这一行：`未拆图` / `已拆图 · 22 部件 · 可做动作`。
**没拆图时，动作按钮和生成按钮是灰的**，避免拿半成品去生成动画。
素材改过（比拆图新）会提示「建议重拆」，但仍允许先用着。

**四种动作**

| 动作 | 类型 | 说明 |
|---|---|---|
| **待机** | 循环 | 呼吸起伏 + 2.5D 转头 + 风吹发丝 + 微摆臂 + 眨眼 |
| **行走** | 循环 | 重心上下起伏（双频）+ 左右移重心 + 躯干前倾反扭 + **摆臂（与对侧腿同相）** + **双腿交替迈步（髋摆+屈膝+抬脚）** + 发丝滞后。**原地走**，位移交给引擎 |
| **受击** | 一次性 | 瞬间后仰击退 + 衰减回弹 + 头/发滞后，**下盘同时卸力（绕脚点后仰 + 屈膝 + 撤步抬脚）**，末帧归位，可直接接回待机 |
| **死亡** | 一次性 | **向右后方**塌下去：最后一僵 → 卸力屈膝（上半身先矮一截）→ 加速塌倒 → 触地压扁 → 四肢瘫软 → 闭眼 → **化掉消失**。终结状态：最后一帧什么都没有，播完直接销毁节点 |

> **腿怎么迈**：拆图时 `legwear` 会按连通域拆成 `leg_L` / `leg_R` 两条（左右各一整块，
> 不切片，避免接缝）；生成时每条腿挂 **髋→膝→踝** 三节骨，沿高度做权重渐变，
> 所以膝盖能平滑弯。
>
> 这批角色是**正面朝向镜头**的，所以默认按「向正前方迈步」来驱动（`--leg-axis front`）：
> 迈出去的那条腿**大腿透视缩短**（膝盖跟着抬起，`--leg-squash 0.15`）、整条腿再上抬
> （`--leg-lift 6px`）、脚尖略下垂露出鞋底，膝盖只微弯 45%；支撑腿保持原长踩地。
> 左右摆角只留 30%（`--leg-swing 24°` × 0.3），所以不会像横着挪。
>
> 侧身角色可以用 `--leg-axis side` 回到「绕髋左右摆」的老做法。

**一次生成多个动作（龙骨合并成一个骨架）**

「② 动作」的四个按钮是**可多选**的：勾几个就一次生成几个动作，最后合并导出到
`output\<素材名>\dragonbones\` 里的**同一份** `_ske.json` —— 一个角色、一副骨架、
多条动画（`idle` / `walk` / `hit` / `death`），龙骨里直接切换，不用换骨架、不用导四份文件。

- 只勾「行走 + 受击 + 死亡」→ 龙骨里就只有这三条动画；
- 旁边有 **全选动作** 一键勾满四个；
- 按钮文字会变成 `② 生成 待机 / 行走 / 受击 / 死亡（4 个动作）`；
- 每个动作**各自的时长**：界面上的「时长」改的是当前动作那一格，其余动作沿用各自的默认值/上次调整值（龙骨里每条动画的长度就按这个来）。

> 反过来也成立：分几次单独生成（先出行走、再出受击）也会**累积**到同一个龙骨文件里，
> 同名动画以最新一次为准。也就是说不管你怎么点，一个角色最后只有一份龙骨数据。

**受击时腿也参与（"脚不配套"已修）**

以前受击只转 `torso`，root 整体平移 —— 腿是根不动的柱子，人被推走时脚在地上滑，
上下半身像断成两截。现在下盘做三件事：

| 动作 | 参数 | 默认 | 说明 |
|---|---|---|---|
| 整体绕**脚底中点**后仰 | `--hit-lean` | 5° | root 绕脚点转一点，脚基本不动、上身倒；不再是"只有腰在弯" |
| 撤步腿撑开 | `--hit-step` | 16° | 往受击方向那侧（`--impact-dir` 决定）的腿向外/向后迈出去 |
| 屈膝卸力 | `--hit-knee` | 24° | 撤步腿只弯 35%（弯多了大腿前倾、小腿后收，两个转角互相抵消，鞋反而原地不动） |
| 撤步抬脚 | `--hit-lift` | 4px | 单峰包络：抬一次就落下，不会跟着回弹抖 |
| 脚别滑走 | `--hit-plant` | 0.35 | 腿相对 root 反向平移，脚在地上蹭住；0 = 完全跟着身体滑 |

`--impact-dir -1` 可以让受击方向反过来（向画面右退），撤步腿会自动换成另一条。
这四个参数都在 `gen_idle_bones.py` 里，界面上目前用默认值。

**死亡（death）：从"倒地"改成了真正的死亡**

这条动作以前叫「倒地 fall」，只是"摔了一跤"：落地还会回弹一下、头反向撑着不肯倒，
看着像随时能爬起来。现在改成「死亡 death」，改动集中在**节奏**和**收尾**：

| | 旧：倒地 fall | 新：死亡 death |
|---|---|---|
| 时长 | 1.6s | **2.0s**（倒 52% + 沉降 26% + 消失 20%） |
| 触地后 | 抖一下、回弹 | 只塌一次，过冲一过就彻底不动 |
| 头部 | 反向抵消（还想抬头） | 跟着身体倒，触地后继续往下垂 |
| 手臂 | 张开乱挥 | 被身体带下去，触地后垂到地上 |
| 结尾 | 停在半空、尸体一直躺着 | 闭眼后**化掉消失**，最后 3% 画面全空 |
| 眼睛 | 落地闭眼 | 落地闭眼，一直闭着 |

时间轴（`T` = 动作时长，`--speed` 对整段生效）：

| 时刻 | 事件 |
|---|---|
| 7% | 最后一僵（`stiff`：1px 挺身 + 头一顿） |
| 6% → 52% | `loose` 卸力：屈膝 + 上半身往下塌（脚不离地） |
| 12% → 52% | `ease = u^1.7` 加速倒下（重力，不是匀速；指数再大会变成"突然摔倒"） |
| 52% | 触地：压扁 5.5% + 横向撑开 3%，`hit_k` 指数衰减 |
| 52% → 78% | `settle` 瘫软：手臂垂地、头再垂、身体再沉 2px |
| 80% → 97% | **消失**：先贴地压扁、再收成一点（`--death-vanish 0.20`） |
| 97% → 100% | 画面全空（最后 2 帧一个字都没剩，实测非背景像素 3 个） |

正面朝向的角色如果只把 root 转 86°，看起来就是一块木板往旁边拍下去 —— 那是"侧倒"。
真人倒下时重心是往**斜后方**掉的，2D 里这个"后方"只能用**透视**表达：
躺下后正对镜头的投影会变短（横向略变宽）。所以死亡是几个分量叠起来的：

| 分量 | 参数 | 默认 | 作用 |
|---|---|---|---|
| 侧倾（旋转） | `--death-deg` | 74° | 往**右**倒的主体角度 |
| 后倒（透视） | `--death-back` | 0.18 | 整体缩小 + 纵向略压扁，表示"往画面里倒" |
| 横扫（位移） | `--death-slide` | 12px | 往倒地方向滑一段，脚不再钉在原地 |
| 躺下变宽 | `--death-spread` | 0.05 | 横向略放宽（近大远小） |
| 腿卸力 | `--death-knee` / `--death-leg` | 40° / 10° | 先跪下再塌，腿折起来垫在下面，不是一根被压扁的柱子 |
| **上半身先矮一截** | `--death-buckle` | 9px | 屈膝时躯干下沉、两条腿的髋骨反向抬回来 —— **脚还踩在地上**，看起来才是"膝盖软了" |
| 瘫软后再沉 | `--death-sink` | 2px | 落地后整个人再往地里陷一点（重量感） |
| **别倒太远** | `--death-center` | 0.6 | 绕脚点转 74° 会把重心甩出去很远（实测身体中心 168 → 277，几乎贴到右边），按比例往回拉一部分。0=纯物理，1=几乎不离原位（脚会滑） |
| 落地闭眼 | `--death-close-eye` | 1 | 落地后盖上"闭眼补丁"，**一直闭着** |
| **消失** | `--death-vanish` | 0.20 | 结尾用整段时长的 20% 让尸体消失；`0` = 不消失（需要"尸体留在场上 / 之后复活"时用） |

方向用 `--death-dir`：`1` = 右后（默认），`-1` = 左后。
绕脚底中点做「旋转 + 缩放」时，平移补偿是 `T = P − R·S·P`（只旋转时退化成 `P − R·P`）。

> **下沉为什么不动 root**：脚踩在 root 的原点上，root 一降脚就跟着陷进地面（实测最后
> 几帧被画布底边切掉一截）。所以只降躯干、再把两条腿的髋骨反向抬回来，脚不动 ——
> 视觉上就是"膝盖软了、上半身塌下来"。
>
> 注意符号：spine 里**正角度是往画面左倒**（实测 head.x 147 → 32），所以 `--death-dir 1`
> 实际用的是负角度。别被这一点绕晕 —— 调参时看预览就行。
> 老参数名 `--fall-*` 仍然可用（同一个开关的别名），动作名 `fall` 也当别名，输出统一叫 `death`。

**消失怎么做的（为什么是"缩"不是"淡出"）**

龙骨 5.5 只认 bone 的 translate / rotate / scale，插槽透明度（alpha）不在导出链路里
—— 写成 slot color 的话，Spine 里能看到、Cocos 里看不到，等于白做。所以"消失"用的是
**把 root 缩到 0.2%**：先贴地压扁（横向比纵向慢半拍，像化开），最后一小段收成一点，
最后 3% 的画面真的是空的（实测非背景像素只剩 3 个）。两条链路都认缩放，Spine 和
Cocos 表现一致。

缩放的锚点要从脚点挪到身体中心，否则整个人会被"吸"到脚下：
`Δ = (1-k)·M₀·(B − P)`（`B` 身体中心、`P` 脚点、`M₀` 是没缩之前的旋转+缩放矩阵）。

> **播完死亡再切别的动作**：`idle/walk/hit` 现在都会在 t=0 补一条 root 的静止关键帧
> （位移 0 / 旋转 0 / 缩放 1）。Spine 的动画只影响自己有轨道的属性 —— 不补的话，
> 死亡把 root 缩到 0 又转了 −74°，切回待机就是"人不见了 / 躺着走路"。
> 游戏里正常用法还是：死亡播完 → 销毁这个节点（或隐藏），没有复活时不需要切回。

**死亡闭眼怎么来的（闭眼补丁）**

很多素材的 `head` 层**本身就把眼睛画死了**，眼白/瞳孔/睫毛是另外几层叠上去的。
所以"把眼睛层压扁"只能得到一条缝，底下的眼睛照样睁着 —— 实测就是这样。

拆图时现在会**合成一张"闭眼补丁"** `eyes_closed.png`：

1. 用 `eyewhite / irides / eyelash` 的 alpha 取眼睛区域，膨胀 2px；
2. 用 `head` 层的像素做 **inpaint 修补**（不是纯色填充 —— 纯色会抹平脸颊阴影，像贴了块膏药）；
3. 在每只眼睛的位置画一条微弯的眼线（颜色取自睫毛的深色）；
4. 插进图层栈，排在睫毛之后（压住所有眼睛层），`cls=eye_closed`。

运行时它被挂在**自己的一根骨**上，平时缩到 0.001（看不见），死亡落地后放大到 1 并一直保持。
用**骨的缩放**而不是网格 deform 或插槽切换，是因为龙骨 5.5 只认 bone 的
translate/rotate/scale —— 这样 Spine 和龙骨两份数据里眼睛都会真的闭上。

> 体检单里会多出一格「闭眼补丁(死亡用)」，这是正常现象。
> 素材没拆到眼睛（没有 eyewhite/irides）时不会生成，死亡会退回"压扁眼睛层"
> （那种方式龙骨里看不到，日志会说明）。关掉用 `--no-closed-eyes`。

支持三种素材：

| 类型 | 说明 |
|---|---|
| **分层 PSD** | 直接拖 `.psd`，自动逐图层导出（含隐藏层），图层位置就是部件坐标 |
| **分层 PNG 文件夹** | 一堆切好的 PNG。若文件夹里带 `coords.json` 就用它的坐标；否则按文件名语义自动排层（位置是估的，可能不准） |
| **一张平面图（AI 自动拆图）** | 拖 `.png/.jpg`，用 see-through / LayerDiff3D 大模型自动拆成头发、脸、五官、手臂等 20 来层，再自动补被遮挡的部分。**需要先装拆图组件，见第三节** |

**推荐用 PSD 或带 `coords.json` 的文件夹**，坐标准确，效果最好。

`coords.json` 格式：

```json
{
  "fps": 24,
  "canvas": {"w": 1024, "h": 1024},
  "parts": [
    {"name": "back_hair", "image": "back_hair.png",
     "x": 210, "y": 60, "width": 600, "height": 700, "grid": [8, 8]}
  ]
}
```

`x,y` = 该 PNG 左上角在画布中的像素位置（y 向下）；`parts` 数组顺序 = 图层顺序（**先画的在前**，最上层在最后）。

## 三、AI 自动拆图（一张平面图 → 分层）

包里默认**不带**这部分（太大），第一次用点界面上的 **「安装 AI 拆图组件」**，程序会自己下：

| 下载内容 | 体积 |
|---|---|
| PyTorch (CUDA 12.8) + torchvision | 约 3GB |
| diffusers / transformers / bitsandbytes 等 | 约 2GB |
| 模型 `layerdiff3d_nf4` / `marigold_nf4` / `marigold-base(text_encoder)` | 约 6.7GB |

**硬件要求：NVIDIA 显卡**，显存 6GB 以上（实测峰值显存 4.6GB）。拆一张图约 2~4 分钟。
装好后模型在 `models\`，依赖装进包内的 `python\`，整个目录仍可整体拷贝给别人。

拆图效果：自动分出 back hair / front hair / head / face / eyewhite / irides / eyelash /
eyebrow / nose / mouth / ears / neck / topwear / **legwear（腿+鞋）** / bottomwear / footwear /
headwear / neckwear / tail / wings / objects（手持道具），手臂再自动切成
大臂-小臂-手三段、腿拆成左右两条（各一整块，靠骨链弯曲而不是切片），被遮挡的部分由模型补全。

> **图层白名单**：模型一共能分 24 个 slot，`build_from_seethrough.py` 里的 `Z_ORDER`
> 必须把它们**全部列上** —— 漏一个就等于把该部位整个丢掉（早期版本漏了 `legwear`，
> 所以拆出来的角色没有腿）。程序会自动检查模型输出里有没有"有内容却没被读取"的图层并报警。
>
> **残影补偿**：模型偶尔会把某块内容漏分配给任何 slot（实测：盾牌、头巾）。这些像素
> 不属于任何部件，合成出来就"凭空消失"。装着完成员件后，程序会拿原图对比，
> 把**没被任何部件覆盖**的连通块捡回来，命名成 `<最近部件>_overlay`：
> 名字决定图层顺序，`cls` 决定挂哪根骨（例如头巾 → 挂 head，不会跟着头发飘）。
> 日志里会打印 `残影 xxx_overlay ...`；不想要可以加 `--no-fill-missing`。
>
> **面部叠放自检**：模型给的 `face` 常常只是一块平整的皮肤底板（有时干脆是白板），
> 按默认顺序压在 `head` 上会把 head 里**已经画好的五官整片盖掉** —— 脸变成没有
> 眼睛、没有嘴的白板，只剩拆出来的眼白/瞳孔浮在上面。所以装配完会拿原图实测
> 「face 压 head」和「face 垫 head」两种叠放，取更像原图的那个（差异通常能从
> 90 降到 40），日志打印 `面部叠放自检: ...`。
>
> **小特征不再被当噪声丢掉**：`irides`（红瞳）这种只有一百多像素的层以前会撞上
> "太小"阈值被丢弃（眼睛没瞳孔）。现在按槽位给阈值：眼瞳/鼻/嘴/眉/睫 30px 起，
> 整块部件 200px 起，残影补偿 200px 起。
>
> **手臂层级**：`大臂`排在躯干**之前**（被护肩、衣袖盖住，不再压着盔甲），
> `小臂 / 手`排在最后（手要压在裙甲和刀柄上，不然手会钻进衣摆里）。
> 最终 z 序由 `Z_RANK` 决定，按名字前缀匹配，`xxx_overlay` 自动继承 `xxxx` 的层。
>
> **头盔/头巾只留头和布**：头饰部件是按"该区域内非肤色前景"重建的，会把画在脸上的
> 眉、眼、闭眼补丁，以及头巾带下面那层额头皮肤一起框进来（suo 实测 324px）。
> `fix_headwear.py` 现在按颜色挑掉这些像素（只摘"颜色也是五官那个色"的，免得把压在上面
> 的黄头巾削出洞），再按"每列黄布最低点"切掉带子下面的皮肤，最后闭运算补掉针眼。
> 结果是部件里只剩头盔 + 头巾（含垂布）+ 背后剑柄。拆图结束时会自动跑（scarf / helmet 模式）。
>
> **手臂只留手臂**：`handwear` 切出来的大臂矩形常把躯干带进来（suo 左大臂内侧挂了 660px
> 深色胸甲）。`trim_arm_body()` 现在的判据是"被 topwear 图层覆盖 **且**（接近衣服主色
> 或颜色偏暗）"，金属高光要么不被覆盖、要么够亮，不会误伤。日志打印
> `手臂去身体: arm_upper_L 剔掉 674px`。
>
> **肩甲 + 大臂从上衣层切出来**：模型只把"肘以下"分进 `handwear`，重甲角色的大护肩、
> 布袖留在 `topwear` 里 —— `arm_upper` 只剩几根描边碎线，肩甲永远钉在躯干上。
> `split_arm_from_body()` 以**前臂当锚点**（肘点 + 前臂宽高）推一个 8 点多边形，
> 从上衣层切出 肩甲+大臂，然后**把这块从上衣层挖走**、洞里压暗当投影（只复制不挖
> 等于把肩甲钉在原处）。手臂 `_z_arm = 22` 压在上衣前面。
> 日志打印 `肩甲切分 L: 上衣层切出 肩甲+大臂 3506px -> arm_upper_L.png 60x98`。
> 已经独立的大臂（quan/suo/pi 这类）会自动跳过；`--no-arm-from-body` 关、`--arm-from-body` 强制。
>
> **白底图的"白洞"**：`src_img` 会把"烟雾/发丝之间那块白"还原成不透明纯白，跟着图层进部件。
> `white_holes()` 按"三通道 >226、连通块 ≥300px、≥45% 是纯白"抠掉（`--white-min` 可调）。
> 原图自带透明通道时整步跳过 —— 否则会把白刀面当背景吃掉。
>
> **长袍角色从衣服里切腿**：`legwear` 空、腿甲算进 `topwear` 时没有腿骨。`split_legs_from_body()`
> 按"髋线（脚底往上 0.47 身高）以下"切下肢 → 分左右 → 按膝高切上下两段 → 上衣挖洞压暗。
> 日志打印 `腿(从上衣层): 髋线 y=183, 切出 4 段 8243px`。
>
> **头发糊住脸**：前发/头饰在脸的位置涂了一块不透明灰时，`demote_hair_over_face()` 用原图
> 把脸补回来并压到五官层下面。日志打印 `头发盖脸: front_hair 覆盖 head 99%`。
>
> **头盔/头巾的层级（重要）**：光在 `Z_RANK` 里给 `headwear` 一个最大值是不够的 ——
> 龙骨这类编辑器导入 Spine 后，会**按骨骼**给 slot 重新排队，头饰原本挂在 `head`
> 骨上（第 3 根），就会排到 `b_face` / `b_head` 之前，头盔被脸皮盖住。现在三层保险：
> 1. 头饰 100% 绑到 `b_head`（"头部画面"那根骨），不再绑 `head`；
> 2. 导出的 slot 逐个写真实骨骼（`slot.bone`），不再全写 `root`；
> 3. `punch_head_wear()` 把头盔轮廓从 `head / face / 眉 / 睫 / 闭眼补丁` 里挖掉 —— 谁先画都一样，
>    头饰和头部各层同骨刚性运动，不会露缝。日志打印 `头饰挖洞: 从头部各层挖掉 Npx`。
>
> **道具跟随手**：`objects` 槽位（刀/剑/盾）和"长在手臂上的残影"会被自动识别成**道具**，
> 按外框重叠面积绑到最近的手臂段（刀→手、盾→小臂），生成时 100% 权重挂到那根骨上，
> 手臂一动武器和盾跟着动。实现：coords 里写 `"cls": "prop", "follow_part": "arm_hand_L"`，
> `gen_idle_bones.py` 把道具挂进同一条手臂链；日志打印 `道具 objects 跟随 arm_hand_L`。
>
> **头饰合并（头巾 / 头盔）**：`back hair / front hair / headwear` 三个槽位加上补在它们身上的
> 残影，会被合成**一整块** `headwear`（一个整体），像素直接取自原图，
> 所以没有接缝也不会串色；日志打印 `头饰整体: 收进 ...` 与 `头饰合并: ... -> 一整块`。
>
> **会剔除五官**：模型的"前发"mask 常常把嘴巴、耳朵也圈进去（实测嘴巴 77%、耳朵 54%
> 的像素落在头巾里），合并时若不剔掉，头巾一飘就带着半张脸一起动。
> 所以合并前会用 `eyewhite / irides / eyelash / eyebrow / nose / mouth / ears`
> 这些部件的 mask 做一次减法，日志打印 `头饰剔除: ... 791px 已摘掉`。
>
> **还会剔掉"不是布料颜色"的碎块**：前发 mask 里可能混着一块眉毛/眼窝（实测 802px，
> 灰绿色、和头巾隔着描边）。这类碎块按连通域找出来，用最大那块（布）的平均色做参考，
> 颜色差得远的小块直接丢掉 —— 日志打印 `头饰剔除: 不是布料颜色的碎块 802px 已摘掉`。
> 丢掉的像素交给下面的脸层，不会再被残影补偿捡回来。
> 这块的 `cls` 是 `headgear`（头盔，完全刚性）或 `cloth`（头巾，包头的部分钉死、
> 下摆才飘）。

**重拆很快**：AI 分层的原始结果会留在 `seethrough_repo\workspace\layerdiff_output\<名字>\`。
同一张图再次拆图时，只要这份结果还在、且比原图新，就直接复用、**跳过 2~4 分钟的 GPU 推理**，
只重新组装部件（改了图层白名单后重拆一次就能拿到腿，不用再跑模型）。

已经有 see-through 环境的机器，可以建一个 `st_env.txt` 直接复用，免去重复下载：

```
PY=D:\xxx\.venv\Scripts\python.exe
REPO=D:\see-through-main
MODELS=D:\see-through-main\models
```

> 拆图代码来自 see-through（Apache 2.0），见 `seethrough_repo\LICENSE`。

## 四、图层命名很重要

程序靠**图层名关键词**判断每个部件是头发/飘带/眼睛/手臂…，从而决定给它挂什么骨骼、怎么动。命名对了效果才对：

| 部位 | 可用关键词（中拼/英文任选，包含即可，大小写无关） |
|---|---|
| 头发 | `hair` `toufa` `fagu` `fasheng` `bang` `braid` `ponytail` `liuhai` |
| 飘带/裙摆/尾巴 | `ribbon` `skirt` `scarf` `cape` `tail` `sash` `qun` `piaodai` `weiba` `lianzi` `zhulian` `leisi` `shipin` |
| 眼睛（会眨） | `eye` `yanbai` `tongkong` `yanpi` `iris` `pupil` `sclera` |
| 眉毛 | `eyebrow` `brow` `meimao` |
| 睫毛 | `eyelash` `lash` `jiemao` |
| 大臂 | `upperarm` `dabi` `shangbi` `shoulder` |
| 小臂/袖 | `forearm` `xiaobi` `xiukou` `xiuzi` `shoubi` `sleeve` |
| 手 | `hand` `shouzhang` `shouzhi` `shoutao` `glove` `jiezhi` |
| 脸/五官 | `face` `lian` `nose` `bizi` `mouth` `zui` `lip` |
| 身体/衣服/脖子 | `body` `shenti` `topwear` `yifu` `torso` `dress` `neck` `bozi` |
| 腿/鞋（可选） | `leg` `legwear` `tui` `footwear` `shoes` `xie` `boots` — 拆图会自动把 `legwear` 分成 `leg_L/leg_R` 两条，行走才迈步 |
| 道具（可选） | `objects` `prop` `weapon` — 手持的刀/盾等，按所在位置跟随躯干 |
| 头饰/帽子 | `headwear` `toushi` `maozi` `hat` |
| 耳朵 | `ears` `erduo` |
| 闭眼图（可选） | `biyan` `closedeye` — 有的话眨眼直接切图，比压扁自然 |

没匹配上的部件会被当作普通片，按所在区域自动补一点飘动。

## 五、参数

| 参数 | 作用 |
|---|---|
| 时长 / 帧率 | 动画长度、采样帧率（30 fps 够用）。切换动作会自动带默认时长：待机 5s / 行走 2s / 受击 0.9s / 死亡 2s（生成时统一 ÷0.75，即播放速度是标称值的 75%） |
| **动作幅度** | 该动作的**主位移与主角度**统一缩放（0~200%）。行走=重心起伏/摇摆，受击=击退距离与后仰，死亡=塌倒角度 |
| **播放速度** | 20%~300%。行走改变步频（同时自动吸附到整数周期，保证循环无缝）；受击/死亡按时间轴缩放，变快后提前归位 |
| 风吹/发丝 | 头发、飘带摆动大小；行走/受击/死亡时改为驱动**发丝的惯性滞后**幅度 |
| 呼吸幅度 | 躯干起伏 + 整体上下浮动 |
| 左臂摆动 / 右臂摆动 | **左右臂分开调**（0~200%，各自独立）。肩/肘/腕 FK 的摆幅统一乘这个倍率；待机、行走、受击、死亡都吃。左右按**画面方向**算：画面左 = 正面角色的右手（拿刀那只常常显得幅度大，就把它调小） |
| 转头幅度 | 2.5D 左右转头（行走时与重心错开半拍） |
| 眨眼 | 关掉就不眨（仅待机/行走可用） |

参数最终都变成 `gen_idle_bones.py` 的命令行开关，想批量出图可以直接调脚本，
不用开界面：`--action walk --act-amp 1.6 --speed 1.2 --cadence 2.2 --arm-l 0.6 --arm-r 1.0` 等。

**批量 / 多动作相关的开关**

| 开关 | 作用 |
|---|---|
| `--action walk,hit,death` | 一次生成多个动作（逗号分隔，顺序就是龙骨里动画的顺序）。`fall`/`die` 是 `death` 的旧名别名 |
| `--out-dir <素材根>` | 多动作时输出到 `<素材根>\<动作>\result.json`；单动作仍可用 `--out` 指定文件 |
| `--duration-map idle=5,walk=2,hit=0.9,death=2` | 给每个动作分别定时长；没写的用内置默认（待机 5 / 行走 2 / 受击 0.9 / 死亡 2） |
| `--duration 2` | 所有动作统一用这个时长（会盖掉 `--duration-map`） |
| `--dragonbones` | 生成完顺手导龙骨；多动作时合并成一个骨架的多条动画 |

```bat
python gen_idle_bones.py --parts output\xxx\parts --coords output\xxx\coords.json ^
    --out-dir output\xxx --action walk,hit,death --fps 24 --preview --cocos
```

## 六、输出

```
output\<素材名>\
  parts\                    ① 拆图产物: 部件 PNG + coords.json
  coords.json               ① 拆图产物: 坐标表
  _split_preview.png        ① 拆图产物: 拆图体检单
  idle\                     ② 动作产物（拆一次图，下面这些目录随便多几个）
    result.json             ← Spine 3.8 骨骼动画，直接导入 Spine
    images\                 ← 贴图（Spine 导入时指向这里）
    _idle_loop.gif          ← 预览（循环动作：待机/行走）
    _idle_strip.png         ← 抽帧条
  walk\ hit\ death\         ② 另外三种动作，同一个 parts 反复生成
    ...
  dragonbones\              ← 【龙骨 DragonBones 5.5】整个角色的骨骼动画，只有一份
    <素材名>_ske.json        骨架 + 插槽 + 网格蒙皮 + 所有动作的骨骼关键帧
    <素材名>_tex.json        图集描述
    <素材名>_tex.png         所有部件打包成的一张图集
```

拆图只需一次，四种动作输出到**各自的子目录**（`<素材名>\idle\`、`<素材名>\walk\`…），
互不覆盖；龙骨则统一放在 `<素材名>\dragonbones\`，一个角色一份文件（多条动画）。
每个动作**同时产出 Spine 和龙骨两套数据**，都是骨骼动画（骨关键帧 + 权重网格），
不是逐帧序列图。重开程序后再拖同一份素材，会自动认出 `output\<素材名>\parts`，
直接就能生成动作，不用再等 AI 拆图。

想不开界面、批量跑也可以直接调脚本（`--parts` 指向已拆好的部件）：

```bat
python split_preview.py --parts output\xxx\parts --coords output\xxx\coords.json
python gen_idle_bones.py --parts output\xxx\parts --coords output\xxx\coords.json ^
    --out output\xxx\walk\result.json --action walk --preview
```

导入 Spine：`File → Import Data → 选 result.json`，图片路径选 `<动作>\images`。
骨架里所有骨都是可编辑的，动画不满意可以直接在 Spine 里改曲线/加骨。

## 七、导入 LoongBones（龙骨）

### 先说结论：LoongBones 不能导入 DragonBones 的 `_ske.json`

LoongBones 的导入面板只认四种东西：它自己的 **json / dbproj**、**Spine 3.8.75**（必须
png + atlas + json 三件一起拖）、**PSD**。它**不提供 DragonBones 数据导入**——只在导出
里提供龙骨格式。所以 `_ske.json` 怎么改都进不去（表现为导不进、或进去后整片红框 Missing）。

**给 LoongBones 用这份：**

```
output\<素材名>\spine\
    <素材名>.json     骨架 + 全部动作（idle / walk / hit / death 合在一个文件里）
    <素材名>.atlas    图集描述
    <素材名>.png      图集
```

把**这三个文件一起选中**拖进 LoongBones 左侧资源库面板，等它加载完即可。
进去之后角色是完整可编辑的骨骼 + 网格 + 权重，想再导出龙骨格式给它自带的引擎，
用 LoongBones 的「导出」即可。

> 打包脚本是 `make_spine_pack.py`（`gen_idle_bones.py --dragonbones` 会自动调它）。
> 单独跑：
> ```bash
> python make_spine_pack.py --spine 输出\walk\result.json:walk ^
>     --spine 输出\hit\result.json:hit --out 输出\spine --name 角色名
> ```

**包里放哪些动作 = 你勾了哪些**

不勾「保留已有动作」时，导出是**覆盖写**：只勾行走，文件里就只有 `walk`。

> 这里踩过一个坑：`spine2dragonbones.convert_multi()` 的 `merge_existing` 默认是 `True`，
> 主导出那一处没传参，于是目标文件里原有的动作会被顺手并回来 —— 表现就是"没勾待机，
> 待机却自己冒出来"。现在这一路显式跟随 `--db-keep`：勾了才并，并在日志打印
> `并入已有动作(--db-keep): [...]`。

**导之前想自检**（不用开编辑器）：

```bash
python spine_render.py output\<素材名>\spine\<素材名>.json
```

按绑定姿态渲染成 `<素材名>_preview.png`。出现完整人形 = 骨架/图集/uv 都对。

### 只导出 Spine，其他格式已取消

生成时默认只产出 `spine\` 三件套（`<名>.png` + `<名>.atlas` + `<名>.json`）。
DragonBones 的 `_ske.json`（以及 `dragonbones\` / `_mesh\` / `_pro\`）**不再默认生成** ——
LoongBones 不支持导入 DragonBones 数据，那几条路是死路。

> 例外：给 **Cocos** 用的 DragonBones 5.5 另外按需导出，见下一节。

## 七之二、导入 Cocos（DragonBones 5.5）

### 版本闸门：Cocos 只认 5.x

Cocos 的 DragonBones 运行时会看数据里的 `"version"`。**6.0 的数据结构导不进去**，
它和 5.5 有两处硬区别：

| | 5.5（Cocos 认） | 6.0（Cocos 报版本过高） |
|---|---|---|
| 顶层 `version` | `"5.5"` | `"6.0"` |
| `armature[0].animation` | **对象**：`{"walk": {...}, "idle": {...}}` | **数组**：`[{"name": "walk", ...}]` |
| skin 名 | 固定 `"default"` | 常带自定义名 |
| 额外字段 | 不写 | `compatibleVersion` 等一批 |

LoongBones 存出来的就是 6.0，所以**不要再经过 LoongBones 中转**：界面勾上「导出 Cocos(5.5)」
（默认就是勾着的），生成后直接拿 `output\<素材名>\cocos\` 三件套。

### 三件套

```
output\<素材名>\cocos\
    <素材名>_ske.json   骨骼 + 插槽 + 网格蒙皮 + 动作（version = 5.5）
    <素材名>_tex.json   图集描述（SubTexture 列表）
    <素材名>_tex.png    图集
```

三个一起拖进 Cocos 资源库 → 得到 `DragonBonesAsset` + `DragonBonesAtlasAsset` →
新建空节点挂 `dragonBones` 组件，把两者填进去，`Animation` 选 `walk` / `idle` / `hit` / `death`。

命令行等价：

```bash
python gen_idle_bones.py --parts ... --coords ... --out-dir output\<名> ^
    --action idle,walk,hit,death --cocos --db-version 5.5
```

可选开关：
- `--db-plain`：每个部件一张图贴骨（**没有**网格形变，兼容性最高；膝盖/头发会整块跟着转）
- `--db-rigid`：刚性四边形网格（无权重，和官方 Pro 导出的形式一致）
- 默认（都不加）：带权重的网格，膝盖、裙摆能弯

### 自检

```bash
python verify_dragonbones.py --work output\<素材名>
```

两套独立实现分别求值 Spine / DragonBones 的顶点世界坐标，逐帧比对。实测四个角色
最大偏差 **0.004px**，说明转换没有几何误差。它会读 `cocos\` 目录（旧的 `dragonbones\`
也认），并且同时兼容 5.5 的对象写法与 6.0 的数组写法。


## 八、常见问题

- **「② 动作」的按钮是灰的、点不动** → 还没拆图。先点「① 开始拆图」，
  状态变成 `已拆图 · 16 部件` 后动作才可用。
- **出了待机，想再出行走，要重新拆图吗** → 不用。拆图是独立的一步，
  换动作只会重新生成动作，直接点「② 生成 行走」即可，parts 不动。
- **想一次把四个动作都出了** → 「② 动作」的按钮可以多选（或点「全选动作」），
  一次生成，龙骨里就是一个骨架 + 4 条动画。命令行：`--action idle,walk,hit,death --out-dir output\xxx`。
- **龙骨文件里只有一条动画 / 找不到某个动作** → 现在龙骨统一在
  `output\<素材名>\dragonbones\`，生成别的动作会**累积**进同一份文件（同名以新的为准）；
  早期版本是按动作分到 `output\<素材名>\<动作>\dragonbones\` 的，重新生成一次即可合并。
- **怎么判断拆图对不对** → 看右边的「拆图体检单」，或者点「检查拆图」重出。
  重点看手臂有没分成大臂/小臂/手三段、五官是否各自独立、名字是否为黄色（没识别）。
- **拆错了** → 点「① 重新拆图」覆盖重做（已生成的动作目录不会被删）。
- **武器/盾不跟手，手臂动了它还杵在那** → 看日志有没有 `道具 xxx 跟随 arm_xxx`。
  没有就是没被认成道具（外框没挨着手臂），把该层的名字改成 `objects` 或重新拆图。
- **手臂盖住盔甲/护肩** → 现在的 z 序把大臂放在躯干下面、小臂和手放在最上面，
  已经是"护肩压大臂、手压裙甲"。要整体调，改 `build_from_seethrough.py` 的 `Z_RANK`。
- **脸被一块白板盖住 / 只剩眼白和瞳孔浮着** → 这是 `face` 层压在 `head` 上。
  现在的版本会自动比对原图选叠放顺序，日志里会看到 `面部叠放自检: ...`。
  如果旧结果已经是错的，点「① 重新拆图」重跑一次（AI 分层有缓存，很快）。
- **头巾/头盔跟着头发飘、飘的时候脸露出来** → 「头部装饰」选**头盔（刚性）**。
  头巾是布、本来就该飘一点，选**头巾（可飘）**：只有垂下来的下摆飘，包在头上的那圈不动。
  已经拆好的图改下拉会立刻生效（要合并成一整块则需重拆一次）。
- **鼻子、耳朵在转头时"自己滑"** → 已修。它们属于"长在脸上"的部件，不再参与 2.5D 视差，
  100% 跟随头部；眼球/眉毛/嘴仍保留一点视差（那是转头的立体感）。
- **拆出来的图没有腿 / 缺胳膊少件** → 先看拆图日志：
  - 打印了 `残影 xxx_overlay` 说明缺的那块已被找回来（在体检单里能看到）；
  - 打印了 `警告: 这些图层有内容但没被读取` 说明白名单漏了类别，把名字加进
    `build_from_seethrough.py` 的 `Z_ORDER` 再重拆。
  - 早期版本确实会把腿丢掉（白名单漏了 `legwear`），现在已修；已有的旧结果点
    「① 重新拆图」即可补上，AI 分层有缓存，不用再等 2~4 分钟。
- **部件飞到左上角 / 层级乱** → 素材文件夹里没有 `coords.json`，自动排层只能靠猜。改用 PSD。
- **头发不飘 / 手臂不动** → 图层名没命中上面的关键词，改名重来（改完重新拆图）。
- **PSD 特别大（8K）** → 自动缩到 2048 内再处理，属正常。
- **生成很慢** → 部件数 × 网格密度决定耗时；60 个部件 5 秒动画大约十几秒。
- **点了拆图提示「未安装」** → 先点「安装 AI 拆图组件」，装完再拖图。
- **拆图报 CUDA / 显存错误** → 没有 N 卡或显存不足（要 6GB 以上），这条路走不了，改用 PSD。
- **拆图下载卡住** → 需要能访问 huggingface.co；若网络不通，可自行设置代理后重试。
- **死亡动画倒出画面** → 正常。倒下是绕脚底旋转的，600px 高的角色在竖幅画布里躺不下；
  预览会自动在倒下的那一侧补留白，导出的坐标本身也允许越界（引擎里由相机解决）。
  预览已自动加左边距，Spine 里把相机/画布放大即可；引擎侧本来就由相机决定，不受画布限制。
- **某只手臂几乎不摆 / 摆幅怪怪的** → 旧版有个 bug：道具（刀/盾）和手共用同一根骨，
  摆臂时道具也往上写角度，把那根骨覆盖掉了（右小臂 2.5° 被写成 0.36°）。已修复，
  现在道具只跟着骨走、不写角度。日志里 `道具 xxx 跟随 arm_xxx` 是正常信息。
- **行走看不出来在迈腿** → 先看生成日志有没有 `腿骨: 2 条 × 3 节`。
  - 没有：说明腿没拆开（两条腿连在一起，`leg_split` 分不出左右），或用了 `--no-leg-split`。
  - 有但幅度小：把「动作幅度」拉到 130~160%，或直接调
    `--leg-squash 0.2 --leg-lift 9 --knee-bend 34`。
  - 默认是**朝正前方**迈步（抬腿 + 大腿透视缩短），不是左右摆；
    侧身角色加 `--leg-axis side` 才是绕髋左右摆。
- **受击/死亡接不回待机** → 受击是**一次性**动画且末帧归零，在 Spine 里把待机设为循环、
  受击设成播放一次，播完切回待机即可。死亡是**终结状态**：末帧不归零、后 18% 完全静止，
  应该播完就停住（不要切回待机），需要复活时再切别的动作。
